## 实施顺序

1. 由 Trellis implement 子代理实施本任务。所有分派以实际 active task 路径开头；实现代理负责 `search.go`、搜索测试、路由和 Web 搜索交互，配合现有修改，禁止撤销他人变更。
2. 先实现受根目录约束的搜索接口和预算机制，补充后端行为/边界测试。
3. 增加搜索表单、范围、结果路径、清除与进入父目录操作；复用预览，处理清除/导航/上传/401 的请求竞态。
4. 增加有意义的前端状态回归测试，并保持现有目录路由测试通过。
5. 由 Trellis check 子代理对照验收标准检查并修复缺陷；主会话核对跨层契约和实际浏览器结果。
6. 按需更新已有前后端规范中的搜索契约；按项目工作流完成提交与收尾记录。

## 风险及回滚点

- 后端遍历代码是资源与文件访问边界重点；检查扫描取消、目录句柄关闭、符号链接循环和部分结果提示。
- `web/app.js` 是异步竞态重点；保留现有请求序号约束并测试迟到响应。
- 新路由、前端入口和测试可整体撤销；没有数据库或持久化索引迁移。
- 浏览器验证服务使用独立端口，不覆盖当前运行服务；完成后向用户提供可试用 URL。
