# 实施计划

1. 加载前端状态、质量规范和后端认证合同，配置实现及检查上下文。
2. 修改 web/app.js：目录 URL、历史记录、初始化恢复、请求竞态处理、错误重试和返回根目录。
3. 修改 main.go 和 web/login.html：携带并验证登录返回目录。
4. 添加必要回归验证：认证跳转、返回地址校验、浏览器导航及特殊字符目录。
5. 运行 go test ./... 与前端语法检查；浏览器验证刷新、历史、失效目录和重新登录行为。
6. 执行 Trellis 检查，更新必要规范并按项目流程收尾；启动本地服务供用户查看。

## 风险

- Go 嵌入静态文件，验证时必须使用重新编译的程序。
- 异步请求和历史跳转必须维持地址、面包屑、列表一致。
- 登录返回地址必须严格限制为站内目录入口。
