# 优化 Web 站点目录路由

## 目标

用户在某个目录刷新页面后仍停留在该目录，避免重新从根目录逐层查找。

## 背景

- `web/app.js:1` 将当前目录保存在内存变量 `current`。
- `web/app.js:109` 初始化调用 `load()`，没有从 URL 恢复目录。
- `web/app.js:56` 的目录加载函数没有同步浏览器地址或历史记录。
- `main.go:239` 使用静态文件服务，任意目录形式的页面路径目前没有对应入口。
- Markdown 已使用 `/markdown.html?path=...` 在新窗口打开；普通文件在当前页面预览。

## 要求

- 刷新页面保留当前浏览目录。
- 目录 URL 使用查询参数，例如 `/?path=项目/docs`，根目录使用 `/`。
- 刷新只恢复目录，不恢复选中的文件预览；文件需要重新选择。
- 浏览器前进、后退按实际浏览顺序切换目录；成功进入不同目录时增加历史记录。
- 登录过期后保留目标目录，重新登录成功后返回原目录。
- 无法访问目录时保留目标地址，显示错误并提供重试和返回根目录。

## 验收条件

- [x] 进入多层子目录后刷新，目录列表和面包屑仍对应原目录。
- [x] 根目录入口仍可正常访问。
- [x] 选中文件后刷新，保留所在目录并回到未选择文件的状态。
- [x] 从根目录依次进入两层子目录，后退和前进时地址、目录列表及面包屑同步变化。
- [x] 子目录页面在登录过期后跳转登录，登录成功后恢复原目录。
- [x] 目录无法访问时地址不变；重试请求原目标目录，返回根目录按钮可正常使用。
- [x] 中文、空格、井号及百分号等目录名可通过 URL 正确恢复。
- [x] 快速导航或连续前进后退时，较早的请求不会覆盖最新目录状态。
- [x] 登录返回地址只允许站内目录入口，不能跳转到外部站点。

## 范围外

- 恢复文件选择、预览进度或滚动位置。
- 更改 Markdown 新窗口预览方式。
- 更换前端框架、增加目录路径形式的后端路由或部署线上服务。
