# 目录路由设计

## 地址与状态

- 使用 URLSearchParams 读取和生成 `path`，根目录采用 `/`。
- 首次加载读取 URL；成功加载后按服务端返回的规范路径 replaceState。
- 用户进入不同目录时产生浏览历史；同目录刷新、上传后刷新和重试不重复增加历史。
- popstate 从当前 URL 加载目录，不新增历史。
- 分离目标目录和已加载目录；错误重试使用目标目录。
- 使用请求序号或取消机制，保证仅最新目录请求能更新页面。
- 切换目录时清理文件选择，失败时避免显示上一目录的面包屑或详情。

## 登录返回

- 后端未登录页面请求及前端 API 401 跳转时携带原目录入口。
- 登录成功解析返回地址，只接受同源的 `/` 或 `/index.html` 目录入口，提取 path 后重建根入口 URL；无效返回地址回根目录。
- 不允许协议相对地址或外部地址造成开放重定向。

## 错误与兼容性

- 失败保留目标地址，重试同一目录，提供返回根目录按钮。
- 现有静态文件入口与 API 合同继续使用。
- 使用标准 URL API 编码特殊字符，路径权限校验继续由后端负责。
- 回滚可还原 app.js、login.html 和 main.go 中本任务修改，无数据迁移。
