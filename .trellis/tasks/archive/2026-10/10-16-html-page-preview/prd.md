# 支持 HTML 文件新窗口网页预览

## 目标

点击 HTML 文件时，在新窗口（由浏览器决定显示为独立窗口或标签页）查看渲染后的网页。

## 实施前事实

- 当前 Markdown 文件点击后在新窗口打开；其他文件进入详情面板（`web/app.js:57`）。
- 当前 HTML 按普通文本预览，现有媒体接口不支持 HTML（`main.go:439`、`main.go:576`）。
- 所有文件访问需要登录，且必须通过现有 `os.Root` 限制在配置根目录内（`.trellis/spec/backend/file-browser-contract.md`）。

## 需求

- R1：支持 `.html`、`.htm`，扩展名大小写不敏感；点击文件直接在新窗口按网页渲染。
- R2：支持页面引用的相对路径 CSS、图片和普通 JavaScript 文件，路径以 HTML 所在目录为基准，并限制在配置根目录内。
- R3：预览页面与文件浏览器隔离，页面脚本不能访问文件浏览器页面、会话存储或以文件浏览器身份调用管理接口。
- R4：保留登录校验、路径边界保护和原有下载能力；其他文件类型行为保持兼容。

## 验收标准

- [x] 点击含中文、空格或特殊字符路径的 HTML/HTM 文件，新窗口显示网页内容而非源码（R1）。
- [x] 嵌套目录页面的相对样式、图片、普通脚本可以加载（R2）。
- [x] 未登录、路径越界、逃逸符号链接均不能读取文件；预览脚本不能访问浏览器管理权限（R3、R4）。
- [x] 原有目录导航、Markdown 新窗口、媒体和文本预览、下载测试通过（R4）。

## 范围外与限制

- 不执行 PHP、Node.js 等服务器程序，不启动项目开发服务器。
- 不保证依赖同源存储、管理接口、ES 模块跨域权限或站点根路径部署的完整应用可运行。
- 用户在实现验收后追加授权：提交代码、编译并更新本地服务；部署前备份当前二进制，重启后验证。
