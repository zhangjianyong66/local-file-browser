# 技术设计

## 架构边界

- 仅调整 `web/index.html`、`web/login.html`、`web/app.js` 和 `web/style.css`，不修改 Go API 与文件安全逻辑。
- 继续使用嵌入式、无框架前端；通过 DOM 渲染、原生 `fetch`、CSS 断点和语义化 HTML 完成交互。
- 以 CSS 变量建立浅色设计令牌：背景、表面、正文、辅助文本、边框、主操作、成功、警告和错误色，保证状态对比度。

## 页面结构与数据流

1. 主页面保留顶部品牌、面包屑、登出和上传入口，增加跳过导航链接与主内容语义区域。
2. 桌面端主内容使用列表/详情双栏：左栏展示当前目录，右栏展示选中文件的元信息、下载和预览；目录点击继续进入目录。
3. 移动端通过状态类切换列表和详情视图，详情提供返回当前目录的按钮，不依赖浏览器后退才能返回。
4. 加载目录、加载详情、上传和预览分别显示稳定的 loading/empty/error 状态，异步按钮在请求期间禁用。
5. 文件行使用语义按钮或链接、图标和文本组合；焦点、悬停、按下和选中状态只改变颜色/背景/边框，不改变布局尺寸。
6. Markdown、纯文本、图片、视频和 PDF 保持既有预览内容，仅调整容器、信息层级和响应式尺寸。

## 兼容性与无障碍

- 所有交互控件可通过 Tab 到达，焦点环可见；图标按钮提供 `aria-label`。
- 状态消息使用 `role="status"` 或 `role="alert"`，颜色不作为唯一信息。
- `prefers-reduced-motion: reduce` 下关闭非必要过渡和进入动画。
- 375px 下禁止横向滚动；媒体使用 `max-width: 100%`，长文件名允许换行。

## 取舍

- 不使用外部图标、字体或前端框架，避免单二进制部署新增网络依赖；图标采用内联 SVG/现有文本语义。
- 不实现搜索、筛选、拖拽上传或后端改造，把改动集中在现有高频流程的可用性。
