# 优化文件浏览器 UI 交互

## Goal

将本地文件浏览器优化为适合高频文件查看、上传、预览与下载的专业工具界面，在不改变既有权限与文件操作边界的前提下，改善信息层级、反馈、响应式行为和可访问性。

## Confirmed Facts

- 前端为无框架的嵌入式静态资源：`web/index.html`、`web/login.html`、`web/app.js` 与 `web/style.css`。
- 现有功能包括单密码登录、目录浏览、面包屑、文件信息与在线预览、下载、拒绝同名文件的上传，以及 Markdown 渲染。
- 当前主界面为浅色单栏列表；文件行仅显示名称、大小、修改时间、MIME，详情区在列表下方显示。移动端仅隐藏两列，未提供独立详情流或加载状态。
- 后端接口与文件安全约束已存在；本任务默认不改变 API 语义、文件访问权限、上传限制或预览上限。
- 使用浅色专业工具风格；本次不提供深色模式。
- 桌面端使用左侧目录列表、右侧详情/预览的双栏布局；小屏幕点击文件进入详情视图并提供返回列表路径。
- 桌面端列表采用紧凑信息密度，移动端增大行高与点击区域；两端共享同一信息层级。
- 上传继续使用文件选择控件，不增加拖拽上传；重点优化进行中、成功、失败和同名冲突反馈。

## Requirements

- 优化登录页和文件浏览器的视觉层级、布局、组件状态与操作反馈，并保持中文界面。
- 提升目录浏览效率：目录层级、当前选择、文件类型、大小、修改时间和主要操作应易于扫读。
- 提升文件详情与预览体验：清楚区分文件信息、预览内容和下载操作；在小屏幕上保有明确的返回路径。
- 上传过程需要显示可理解的进行中、成功、失败和同名冲突反馈，且避免重复提交。
- 支持键盘操作、可见焦点状态、语义化标签和非颜色唯一的状态提示；桌面与手机均不产生横向溢出。
- 采用克制、工具化的视觉设计，动画仅用于表达状态变化，并遵从减少动态效果偏好。
- 不引入前端框架或外部运行时依赖；继续使用浏览器原生 API 与现有 HTTP 接口。

## Acceptance Criteria

- [x] 登录页和主界面具有统一、可读且专业的视觉系统，主要操作、当前目录和当前文件均有明确层级。
- [x] 目录列表在桌面端易于比较名称、类型、大小和修改时间；选中与悬停状态不会造成布局跳动。
- [x] 文件详情可辨识地展示文件信息、预览和下载操作；移动端能进入详情并明确返回列表。
- [x] 上传按钮和上传结果提供禁用、进行中、成功、失败与同名冲突的可见反馈，失败说明可指导用户处理。
- [x] 375px 宽度与常见桌面宽度下没有横向滚动、文字遮挡或被固定区域遮住的内容。
- [x] 键盘可到达所有可交互控件，焦点清晰；图标按钮具有可访问名称；颜色不是状态的唯一载体。
- [x] 用户启用 `prefers-reduced-motion` 时，非必要动画被关闭或显著减弱。
- [x] 现有浏览、预览、下载、登录登出与不覆盖上传行为保持可用。

## Out of Scope

- 修改后端 API、安全策略、认证机制、文件操作能力或预览类型。
- 文件搜索、排序、筛选、批量操作、拖拽上传、在线编辑与目录下载。

## Risks and Deferred Items

- 纯 CSS/原生 JavaScript 改造需要同时维护桌面与移动断点，需重点验证 375px、768px 和宽桌面。
- 不引入新的后端接口；若详情切换需要状态同步，使用 URL 或前端当前路径状态完成，不改变 API 契约。
- 目录搜索、筛选和拖拽上传保留为后续独立任务，避免扩大本次 UI 改造的行为范围。
