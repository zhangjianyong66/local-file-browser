# 实现计划

1. 读取并遵循前端 Trellis 规范，确认现有 API 与测试不需要变化。
2. 重构 `web/index.html` 与 `web/login.html` 的语义结构，加入可访问名称、跳过链接、操作区和详情返回入口。
3. 重构 `web/app.js` 的页面状态：目录列表、当前选择、详情加载、移动端视图、上传状态和错误恢复；保留现有接口调用与路径编码。
4. 重写 `web/style.css` 的浅色设计令牌、桌面双栏布局、移动断点、列表密度、预览容器、焦点/按下/禁用状态与减少动态效果规则。
5. 为上传、目录切换、详情加载、空目录、错误、文本/Markdown/媒体预览补充稳定反馈，确保不会重复提交或布局跳动。
6. 运行格式化、Go 测试、静态检查和可用的浏览器/HTTP 验证；检查 375px 与桌面视口。

## 验证命令

- `go test -race ./...`
- `go vet ./...`
- `go build ./...`
- 启动本地服务后验证登录、目录进入、文件选择、预览、下载、上传成功和同名冲突。

## 风险与回滚点

- 前端状态重构若导致 API 行为回归，优先回退 `web/app.js` 状态层，保留 CSS 令牌和语义结构。
- 移动端视图切换若出现历史路径问题，使用当前目录状态恢复列表，不修改服务端路由。
