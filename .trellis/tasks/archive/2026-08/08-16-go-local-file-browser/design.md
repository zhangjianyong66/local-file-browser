# 技术设计

## 架构边界

- Go 标准库 HTTP 服务负责认证、路径安全、目录 API、文件流式下载/预览和 multipart 上传。
- 前端使用服务内嵌的静态 HTML/CSS/JavaScript，调用同源 HTTP API；不引入账户或外部存储。
- 配置层统一解析根目录、监听地址、端口和密码，启动时规范化根目录并校验可访问性。

## 数据流与契约

1. 请求先经过 Cookie 会话认证中间件（登录接口除外）。
2. 路径参数与根目录拼接后进行清理、真实路径解析和边界校验；符号链接越界一律拒绝。
3. 目录接口返回排序后的条目和元信息；文件接口根据 MIME 决定 inline 预览或 attachment 下载。
4. 上传使用当前目录句柄和排他创建（`O_CREATE|O_EXCL`），避免并发请求覆盖同名文件。
5. 文本预览通过受限读取最多 5 MiB；统计值基于读取内容并明确截断状态。

## 兼容性与运行

- 默认绑定 `127.0.0.1`，可通过参数覆盖。
- 使用 Go 标准库优先，减少部署依赖；通过 `go test ./...` 验证。
- Cookie 设置 HttpOnly、SameSite=Lax；生产 HTTPS 场景支持 Secure 配置。

## 重要取舍

- 单密码而非账户体系，降低部署和维护成本，但不提供用户级审计。
- 不支持修改和目录下载，降低破坏性操作及临时文件风险。
- 内嵌前端，保证单二进制部署。
