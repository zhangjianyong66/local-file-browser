# 增加配置文件与系统服务脚本

## Goal

提供可维护的配置文件、启动/停止脚本和 Linux systemd 服务模板，让本地文件浏览器可以稳定启动、停止和开机自启，同时保留现有命令行参数和环境变量兼容性。

## Confirmed Facts

- 当前 Go 程序支持 `-root`、`-listen`、`-password`、`-cookie-secure` 参数；密码也支持 `FILE_BROWSER_PASSWORD`。
- 默认监听 `127.0.0.1:8080`，默认根目录为 `~/project`。
- 当前环境为 Linux；项目根目录没有现成部署脚本或服务文件。
- 服务需要通过 FRP/Nginx 对外代理，因此 systemd 服务应只绑定本机，并支持独立日志和重启策略。
- 配置文件使用标准库可解析的 JSON 格式；不引入 YAML/TOML 依赖。
- systemd 采用用户级服务；服务默认以当前用户身份运行，不要求系统级安装权限。
- 默认读取程序同目录 `config.json`，可用 `-config` 覆盖；优先级为命令行参数 > 环境变量 > 配置文件 > 内置默认值，密码文件建议权限为 `0600`。

## Requirements

- 增加配置文件，至少覆盖根目录、监听地址、密码、Cookie Secure 和可执行文件/工作目录所需的部署信息。
- 配置文件不能把密码硬编码为必须提交的默认值；支持安全权限提示或环境变量覆盖。
- 保留现有启动参数和环境变量，并定义清晰优先级。
- 提供启动脚本、停止脚本和 systemd 服务模板；脚本使用明确路径和可读错误提示。
- systemd 服务支持开机启动、异常自动重启、日志进入 journald，并以非 root 用户运行。
- 提供部署文档，说明配置文件位置、权限、启停命令、注册服务和验证状态的方法。

## Acceptance Criteria

- [ ] 使用配置文件可以启动服务，且根目录、监听地址、密码和 Cookie Secure 生效。
- [ ] 命令行参数/环境变量与配置文件冲突时按文档优先级工作，现有启动方式不回归。
- [ ] 启动脚本可检查配置/二进制并启动；停止脚本可优雅停止并报告服务状态。
- [ ] systemd 模板不要求服务绑定公网地址，以非 root 用户运行并配置失败自动重启。
- [ ] 文档包含不使用 `sudo` 的用户服务方式，系统级安装的权限边界和验证命令明确。
- [ ] `go test -race ./...`、`go vet ./...` 和 `go build ./...` 通过。

## Out of Scope

- 自动安装 FRP、Nginx 或申请 HTTPS 证书。
- 在网页中修改运行配置或密码。
